|---|---|---|

## v2
(entries appended below as runs happen)
- **v2-0 (replication check, not a variant):** re-evaluated reused v1 `multilevel` seed-0 parameters under the v2 code (in_dist, 12 robots). Per-robot performance matches v1 to ~0.002 (GPU atomics non-determinism). A first read of the console log looked like a 2x discrepancy but was the "agent 0 disabled" line, not the intact line. Reused seeds 0-2 parameters are therefore valid.
- **v2-1 (main run):** tag `v2`; conditions central / multilevel / multilevel_comm; seeds 0-4 (0-2 reuse v1 trained params, 3-4 trained fresh, 60 iters, clip 0.08, 12 groups); envs in_dist, wind, sand, slope_up, step_down; lesions: modules k=0-3, top_conn, pair_conn.
- **v2-2 (P2, single pre-specified attempt):** tag `v2_p2`; multilevel_joint and multilevel_comm_joint; agent MLPs unfrozen, 120 iters, clip 0.08, 12 groups trained on the test robots, seeds 0-4, same envs/lesions.
- **v2-1 failure (logged):** the main run crashed while training `central` seed 3 (about iteration 20). The crash itself was a logging bug (max over an empty selection when every robot's loss was non-finite), but it means all 12 robots had non-finite loss at once. Possible cause: two processes each claiming 99% of GPU memory (the README warns of NaNs when a simulation does not fit); P2 was running concurrently. Checks: seeds 0-2 evaluation under the same load matched v1 (max |diff| 0.0035, no NaNs); P2 seed-0 training histories had no non-finite values. Fix: logging made robust and now reports the non-finite count. Training regime unchanged; main run resumed (existing parameters skipped).
- **v2-1 failure #2 (logged):** the resumed `central` seed-3 training again went non-finite: 10 of 12 robots at the same iteration (13), identical in both attempts; those robots then kept best-so-far weights from iteration <=12 (undertrained: best perf 0.04-0.41 vs 0.10-0.72 in seeds 0-2). Seeds 0-2 `central` (trained alone in v1) had 0 non-finite robots. Both failures occurred while the P2 run shared the GPU (both processes claim 99% of device memory). Hypothesis: memory contention (README warns of NaNs when the simulation does not fit). Action: discard that seed-3 `central` parameter file (moved to `results/v2/_discarded/`), stop the concurrent P2 run (its finished seed-0 parameters are kept; histories had 0 non-finite values), rerun main alone. If `central` seed 3 diverges again when alone, the cause is intrinsic and a numeric guard will be added and logged.
- **v2-1 resolution:** `central` seed 3 retrained alone with the identical regime (same seed, groups, iteration-0 loss): 0/12 non-finite robots at every logged iteration, final mean best-training perf in the normal range. Hypothesis supported: the NaNs were GPU memory contention from running two jobs concurrently, not a property of the method. No numeric guard was added; training regime unchanged. Policy from here: one GPU job at a time. Contended seed-3 rows moved to `results/v2/_discarded/`.
- **v2-1 outcome (main):** complete, 5 seeds x 5 envs x 3 conditions, 15,300 rows, 0 non-finite values. `step_down` passed the pre-specified inclusion rule (intact distance central 0.297, multilevel 0.245, both >= 0.10) and is included. Results in `results/v2/summary.md`.
- **v2-2 outcome (P2, single attempt, as pre-specified):** complete, 12,240 rows, 0 non-finite values. Primary comparison (k=1 retention, comm_joint minus multilevel_joint): -1.6 pct points, 95% CI +/- 5.0 across 5 seeds -> no benefit. Exploratory (not pre-specified as primary): intact distance was higher with communication, +0.060 +/- 0.032 (paired across seeds, ratio 1.15; CI excludes 0), but retention did not improve. Not repeated or tuned.
- **Not done (out of scope per the change list):** richer learned message vector in P2; physical module removal; >3 levels; central controller initialised from pretrained agents. P2's agent MLPs are trained per robot on the test robots, so P2 intact distances are not comparable to the main conditions.
